# LearnWith Mahidhar

Interview-prep site for Java, Spring Boot and Microservices. Built with [Docusaurus](https://docusaurus.io) (docs-only mode), deployed to GitHub Pages at <https://learnwith.mahidhardurga.in>.

## Run locally

```bash
npm install
npm start        # dev server at http://localhost:3000
```

Note: the local search index is only generated by a production build. To try search, run `npm run build && npm run serve`.

## Build

```bash
npm run build    # outputs to ./build, fails on broken links
npm run serve    # serve the production build locally
npm run typecheck
```

## Deploy (GitHub Pages)

Deployment is automated by `.github/workflows/deploy.yml` on every push to `main`.

One-time setup:

1. Push this repo to GitHub.
2. Repo **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. Under **Settings → Pages → Custom domain** enter `learnwith.mahidhardurga.in` and enable **Enforce HTTPS** once the certificate is issued.
4. At your DNS provider add a `CNAME` record: `learnwith` → `<your-github-username>.github.io`.

`static/CNAME` keeps the custom domain across deployments.

## Writing a page

Every page needs front matter:

```yaml
---
title: Spring Boot Auto-Configuration
description: One-sentence summary used for SEO.
keywords: [spring boot, auto-configuration, interview]
sidebar_position: 2
---
```

Use ```` ```mermaid ```` blocks for diagrams. Link other pages with relative paths to the `.md` file, so broken links fail the build.

## Ad-ready structure (Phase 2 later)

Layout is swizzle-friendly: run `npm run swizzle @docusaurus/theme-classic DocItem/Layout -- --eject --typescript` (or `Navbar`, `DocSidebar`) to add ad slots in the header, sidebar or between sections. No ad or analytics code exists yet.

## UI customisations

- `src/pages/index.tsx` + `index.module.css`: the landing page (hero, tech-stack cards, labs). Page counts are computed from the docs, not hard-coded.
- `src/data/flashcards.ts` + `src/components/Flashcards/`: the 60-second quiz. Add cards by appending to the array (link each to a docs page).
- `src/components/progress.ts`, `MarkComplete.tsx`, `src/theme/DocItem/Footer`, `src/theme/DocSidebarItem/Link`: "Mark as done" button and sidebar ticks. Progress lives only in the visitor's `localStorage`; nothing is sent to any server.
- `src/css/custom.css`: design tokens and theme (dark by default). Fonts are self-hosted through `@fontsource-variable/*`, so no request goes to Google Fonts.
- The docs intro is served at `/guide`; `/` is the landing page.

## What a topic page shows

Every topic page shows exactly three things: the title, a short **Definition**, and **Example code**. There are no experience levels.

How it works:

- `plugins/rehype-lesson-parts.mjs` builds each page at build time. It keeps the title, adds the definition from `src/data/lessons.json` (`def`), and picks one example: `example` from `lessons.json` if given (title, lang, code), else the code block from the section named by `exampleFrom`, else the best-looking code block in the page. Pages with no code (a few conceptual ones) show only the definition.
- Everything else written in the markdown files (explanations, interview questions, quizzes, labs, takeaways) stays in the files but is **not shown**. To bring a page back to its full version, remove its entry (or just its `def`) from `lessons.json`. The pages listed there also have `hide_table_of_contents: true` in their front matter; remove it when you show the full page.
- Pages without a `def` (the cheat sheets and the three question banks) are shown exactly as written.
- **Sub-topics** (a tree under a topic, for example OOP -> Encapsulation, Abstraction, Inheritance, Polymorphism): list them in `src/data/subtopics.json` (`{"java/core-java/oop-and-design": {"label": "OOP and design", "subs": ["encapsulation", ...]}}`). Each sub-topic is a page `docs/<topic path>/<slug>.md` that contains only the front matter and `# Title`; its definition and example live in `lessons.json` under `/<topic path>/<slug>`. `sidebars.ts` turns the topic into a category linked to the topic page with the sub-topics inside it. Every Java example is compiled and run before it is added (the real output is appended as a comment). Topic counts on the home page come from `pages.json`, so sub-topics are not counted.
- **Grouped by Java version**: `java/core-java/modern-java` in `subtopics.json` has `versions` instead of `subs`: a list of `{label, items}` where each item is a doc id. `sidebars.ts` makes each version a category (with an automatic overview page) holding its features. Features sit in the version that introduced them as a final feature (for example Records in Java 16, Streams and lambdas in Java 8). Versions with no final feature of their own (13, 19, 20) have no section.
- `src/data/pages.json` lists every guide page (path and short title). Add new pages there.
- `npm run validate:content` checks `lessons.json` against the pages. Restart the dev server after editing `lessons.json` or the plugin; if a change does not show up, delete `.docusaurus` and `node_modules/.cache`.

**Writing style for definitions:** two or three short sentences, everyday words, the real definition first. No jargon without a one-line explanation.

**Interactive components** (kept in the code but not shown on topic pages at the moment; `src/components/Interactive/`, registered in `src/theme/MDXComponents.tsx`):

- `<Outcomes items={[...]} />` goes before the first H2. `<Checkpoint questions={[{q, options, answer, why}]} />` goes under a `## Check yourself` heading.
- Labs: `HashMapLab`, `SagaLab`, `KafkaLab`, `CircuitBreakerLab`, `TokenBucketLab`, `IsolationLab`, `TokenCostLab`, `RagLab`, `AgentLab`, `GuardrailLab`. Put each under a `## Try it: ...` heading; it lands in part 9.
- The sticky bar under the breadcrumbs (`src/components/LessonBar.tsx`) shows topic N of M for the section, reading progress and reading time. Reading order is the `sidebar_position` front matter.

### Navigation and layout (keep it simple)

- Navbar: **Topics** (dropdown to each section's overview), and **Quiz**. Add new top-level sections to the Topics dropdown in `docusaurus.config.ts`.
- The sidebar is built in `sidebars.ts`: one section per folder in `docs/` (order and label from its `_category_.json`). Inside a section the topics are grouped by hand in the `GROUPS` table (for example Java: Language basics, Collections, Concurrency, JVM) while the files stay where they are, so URLs do not change. A section that is not listed in `GROUPS` (AI) uses its folders as groups. To add a topic, add its doc id to a group.
- Every page needs a short `sidebar_label` in its front matter (the sidebar is narrow; the full `title` is for SEO). One sidebar section is open at a time.
- The homepage is a compact hero, one card per tech stack (Java, Spring, Microservices, GenAI and more) and the labs. The quiz lives at `/quiz`.
- The look is Apple-style: neutral surfaces, system font stack, translucent navbar, soft rounded cards. Colours and spacing are tokens at the top of `src/css/custom.css`.
